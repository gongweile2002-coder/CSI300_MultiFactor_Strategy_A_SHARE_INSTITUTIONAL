# A股实盘操作指南（v9）

修订日期：2026-09-12。v9 新增流程先看同目录《V9日常运行与升级说明》。先完成本机演示、真实数据验证和券商环境联调。代码正确性不等于策略有正收益；本包没有你的账户资料、实时授权数据或实际成交记录。

## 1. 环境和配置

在项目目录运行 README 的安装命令。普通数据分析、计划和人工对账可在 Windows/macOS/Linux 上运行；MiniQMT 需在券商支持的 Windows 环境，先安装、登录并运行券商提供的终端和 xtquant。不要盲目把不匹配版本的 xtquant 覆盖进券商环境。

复制 `config/live.example.json` 为 `config/live.local.json`。初次保留 `live_enabled=false`。所有 v8 命令的公共参数放在子命令之前：

```bash
python live.py --config config/live.local.json --journal ops/live_v8.sqlite3 demo
```

没有 `live.local.json` 时，直接使用示例配置即可演示。`allowed_buy_boards` 可包含 `MAIN`、`STAR`、`CHINEXT`；启用板块必须与券商实际权限一致，配置文件不能开通券商权限。仅支持普通股票现金账户，不能混用信用账户数据。

资金和证券字段必须包含**整个账户**。不得只导入本策略想买的股票而遗漏其他持仓。原有非成分股票也必须提供原始估值、行业、ADV 和交易状态；未下载到参考数据时会停止。含 ETF、北交所股票等本版未支持资产的账户，不能靠删除这些持仓行来绕过检查。

## 2. 下载真实数据和生成信号

将 `.env.example` 复制为 `.env`，本机填入自己的 `TUSHARE_TOKEN`，不要提交到代码仓库或分享压缩包。下载器自动读取该文件。

```bash
python download_live_data.py --output data/live --lookback-years 3 --sleep 0.15
python live.py prepare --data data/live --output outputs/v8_signal
python live.py check --data data/live
```

下载需要指数成分、未复权日线、复权因子、daily_basic、财务指标、历史行业、ST、涨跌停和交易日历等接口权限。权限或下载失败应解决数据来源问题；不要手工伪造清单或把空 CSV 标记为成功。初次全历史下载请求较多，可按实际权限调整请求间隔。

日线完成时间按北京时间 **18:00** 保守处理。交易日上午下载的最新有效日为前一交易日；信号使用相同口径。实际数据源仍未更新时会停止。日历含所有自然日和明确休市标记，不用周一至周五推算法定假期。

下载范围覆盖选定期间的沪深300历史成分并集；不使用按代码排序的前50只样本。文件清单通过 SHA256 防止下载中断或文件混改，**这只是完整性检查，不是第三方数据真实性认证**。当前成分原始行情、估值覆盖不足95%时停止；正常停牌也可能导致保守停用，需要先核实原因。

`outputs/v8_signal` 内：

| 文件 | 用途 |
|---|---|
| `targets.csv` | 股票、目标权重、信号日、信号原始收盘价和策略版本 |
| `factor_audit.csv` | 合格横截面和评分，便于检查财报、估值日期 |
| `execution_reference.csv` | 信号日参考价格、行业、前20交易日 ADV、ST/退市标记 |
| `signal_report.json` | 合格数量、总仓位、均线状态与数据来源限制 |

本版实盘链路不做 ML 选股，不按历史最高收益挑选因子权重。日报更新不代表每天必须交易；盘中调仓带、资金、手数和日换手限制可能产生零委托。建仓可能分多日完成。本版对所有支持板块保守限制单笔10万股，不自动拆分多笔；大账户也不会绕过该上限。

## 3. 人工委托路径

这是没有 MiniQMT 时的可用路径，需要你从券商或可信实时行情源取得标准格式的数据。程序不会伪造券商可卖数量，也不提供未经适配的任意券商 CSV 自动识别。

盘中取得 `ops/account.json`、`ops/quotes.csv`，然后：

```bash
python live.py --config config/live.local.json plan --account ops/account.json --targets outputs/v8_signal/targets.csv --quotes ops/quotes.csv --calendar data/live/trade_calendar.csv --output outputs/v8_plan
```

查看 `outputs/v8_plan/orders.csv` 和 `blocked.csv`，核对股票、方向、数量、限价、估计费用和拦截原因。`plan.json` 的 `plan_hash` 是完整内容校验值，`expires_at` 是计划失效时间。v9.2 默认只允许在生成后 10 分钟内登记/提交；行情变化或计划过期时，应刷新数据重新生成。

自动生成交易指令也可能属于程序化交易。先向券商确认适用的报告要求和账户权限，再将 `broker_rules_confirmed` 改为 `true`。这项配置只记录你的确认，不代替券商办理。

复核后用实际完整的校验值替换下面的 `HASH`：

```bash
python live.py --config config/live.local.json manual-register --plan outputs/v8_plan/plan.json --confirm-plan HASH --account ops/account.json --targets outputs/v8_signal/targets.csv --quotes ops/quotes.csv --calendar data/live/trade_calendar.csv
```

登记成功后，订单在本地台账中的状态是 `APPROVED`，它只表示“已复核并预留”，**不表示已经送达券商**。按 CSV 原限价和数量在券商终端提交，不得把 CSV 导入模拟器后当作真实成交。人工输入也应使用同一委托编号映射真实券商委托号；检查是否输错方向和数量。

把真实券商**累计**回报填入 `ops/broker_reports.csv`，列格式见 `config/broker_reports.example.csv`：

```bash
python live.py reconcile --reports ops/broker_reports.csv
python live.py ledger
```

| 回报字段 | 含义 |
|---|---|
| `client_order_id` | orders.csv 中的策略委托编号，原样保留 |
| `broker_order_id` | 真实券商委托号，按文本保存 |
| `status` | SUBMITTED、PARTIAL、FILLED、CANCELLED、REJECTED、UNKNOWN；本地未提交过期可用 EXPIRED |
| `filled_qty` | 此委托迄今累计成交股数；不是本次新增股数 |
| `avg_fill_price` | 累计成交均价；未成交时为0 |

仅受理为 `SUBMITTED,0,0`；部分成交为 `PARTIAL`；全量成交才能填 `FILLED`。部分成交后撤单填 `CANCELLED` 并保留已成交量和均价。重复同一累计回报不会重复记账，回报倒退、超量、非法状态回退或与限价矛盾会停止。`REJECTED` 表示券商/接口明确拒绝，不要用它表示“自己没有提交”。

若已登记为 `APPROVED` 但实际没有提交，计划到期后可以运行 `python live.py expire --account-id YOUR_ACCOUNT`，程序只把本地未提交的过期 `APPROVED` 标记为 `EXPIRED`，不会联系券商。若无法确认订单是否曾经发出，应保持/记录为 `UNKNOWN` 并查询券商；不要删除台账重发。同一股票同一方向当天已经登记过，即使拒绝、撤单或过期，也保留重复防护；不建议靠换策略 ID 绕过。

## 4. 账户和行情字段

账户 JSON 必填示意（数值必须改为同一时点的真实信息）：

```json
{
  "source": "broker",
  "account_id": "YOUR_ACCOUNT_ID",
  "as_of": "YYYY-MM-DDT10:00:00+08:00",
  "risk_reference_date": "PREVIOUS_TRADING_DATE",
  "cash_available": 97000.0,
  "cash_total": 97000.0,
  "total_asset": 100000.0,
  "prior_close_nav_adjusted": 100000.0,
  "high_water_nav_adjusted": 100000.0,
  "open_order_count": 0,
  "positions": [
    {"ticker":"600000.SH","qty":300,"sellable_qty":100,"last_price":10.0}
  ]
}
```

`cash_total` 包括冻结资金，`cash_available` 仅指可买证券资金。`total_asset` 应等于总现金加全部证券市值，并使用同一估值口径。`sellable_qty` 必须来自券商；不能把总持仓直接当可卖数量，也不能靠持仓导入日期推断 T+1。

`risk_reference_date` 必须是日历中的前一交易日，缺失或过期会停止；不要只改日期而保留旧净值。`prior_close_nav_adjusted` 是调整出入金后的前一交易日收盘总净资产；`high_water_nav_adjusted` 是相同资金口径的历史高水位。金额单位都是元。本版没有自动份额净值账户：出入金、转托管等需要你从券商流水维护基准，不能每日重置高水位。账户高水位低于昨收会拒绝。数据错误或无法解释的大额变动应停止交易并对账。

行情 CSV 必填列：

```text
ticker,quote_time,last,bid,ask,up_limit,down_limit,status,price_basis,adv20_cny,industry_l1,is_st,is_delisting
```

- 代码用 `600000.SH` 或 `000001.SZ`，保留前导0。时间带北京时间偏移，例如 `2026-09-11T10:00:00+08:00`，实际用运行当天时间。
- `last/bid/ask` 是未复权最新价、买一价、卖一价；`price_basis` 固定 `raw`。涨跌停价取当天证券资料，不用统一10%或ST比例硬推。
- `adv20_cny` 是截至信号日已完成的前20交易日日均成交额，单位人民币元，不能用当日尚未完成成交额。
- 状态为 `TRADING` 或 `SUSPENDED`，未知状态不能强填正常；风险标记只能为 true/false 或 1/0。
- 覆盖目标与全部已有持仓。没有买卖盘、停牌行情时间陈旧、无有效涨跌停价或 IPO 无涨跌幅限制时，程序会拒绝相应订单或停止整份计划。

账户最多120秒、行情最多30秒。手工导出的实时数据往往很快过期；这时应重新导出并规划，不能只改时间戳。人工流程主要适用于具备可信实时导出能力的券商环境。

## 5. MiniQMT 路径

在券商支持的 Windows 电脑启动并登录 MiniQMT。以下为 PowerShell，会话环境变量只在本机设置；路径用自己的终端 userdata_mini 目录。

```powershell
$env:QMT_USERDATA_PATH = 'C:\YourBroker\userdata_mini'
$env:QMT_ACCOUNT_ID = 'YOUR_ACCOUNT_ID'
```

复制 `config/risk_reference.example.json` 为 `ops/risk_reference.json`，填前一交易日日期、真实调整后昨收净资产和高水位。这份风险参考不会自动从历史成交重建。

只读抓取：

```powershell
python live.py qmt-snapshot --reference outputs/v8_signal/execution_reference.csv --risk-reference ops/risk_reference.json --calendar data/live/trade_calendar.csv --targets outputs/v8_signal/targets.csv --output outputs/v8_broker
python live.py --config config/live.local.json plan --account outputs/v8_broker/account.json --targets outputs/v8_signal/targets.csv --quotes outputs/v8_broker/quotes.csv --calendar data/live/trade_calendar.csv --output outputs/v8_plan
```

首次联调先核对资金、冻结资金、总资产、全部持仓、可卖量与终端一致；让券商提供的模拟/测试环境覆盖受理、部分成交、撤单、断线恢复等场景。本包的 SDK 替身测试不能代替这一步。

实际下单时必须同时满足：`live_enabled=true`、`broker_rules_confirmed=true`、本机环境变量明确开启、完整计划已复核。**下面的命令具备真实交易能力，仅在上述验证完成后由你本机操作。**

```powershell
$env:QMT_ENABLE_LIVE = 'YES_I_UNDERSTAND_REAL_ORDERS'
python live.py --config config/live.local.json qmt-submit --reference outputs/v8_signal/execution_reference.csv --risk-reference ops/risk_reference.json --calendar data/live/trade_calendar.csv --targets outputs/v8_signal/targets.csv --plan outputs/v8_plan/plan.json --confirm-plan HASH
```

提交时先检查 `plan.json` 是否仍在有效期内，再重新查询账户、盘口和交易状态；若新计划的股票、股数或价格变化，停止并要求重新复核。每笔在调用券商 SDK 之前先把本地状态写成 `SUBMITTING`，随后再检查可卖量、实际持仓、现金、集中度、信号偏离和保守的价格笼子。限价委托可能不成交；本版不会自动追价或自动撤单。

券商返回正委托号只表示受理，随后查询累计回报：

```powershell
python live.py qmt-reconcile --reference outputs/v8_signal/execution_reference.csv --risk-reference ops/risk_reference.json --calendar data/live/trade_calendar.csv
python live.py ledger
```

发现错误委托，先在券商终端查询或撤单，再对账。不要把“撤单请求已发送”当成“已撤”；成交和撤单可能同时发生。没有匹配回报的 `UNKNOWN` 保持阻止状态，需查询历史委托或券商支持，必要时用已核实的报告文件对账。`live.py ledger` 还会显示本地 `reserved_cash` / `reserved_sell_shares` 汇总；它用于防误操作，不替代券商真实冻结数据。

## 6. 每天怎样使用

1. 收盘数据完成后：下载/校验真实数据、生成下一交易日信号，保存当日目标和因子审计。
2. 下一交易日盘中：核对本机时间、交易日历、账户基准和历史未完成委托，再获取最新快照。
3. 先生成计划并检查拦截原因；复核后登记人工委托或提交 MiniQMT 限价委托。存在待成交卖单时，买单不提前使用卖出款项。
4. 查询成交、撤单等最终状态。卖出完成并对账后刷新账户，可再规划尚未登记的买入。实际费用以交割单为准。
5. 收盘核对终端总资产、现金、持仓、可卖量、成交和费用；备份整个 `ops`、配置和当天输出。先关闭程序再备份 SQLite；运行中复制时必须同时处理 WAL/SHM，不能只拷主数据库。

使用同一账户时，所有进程和操作电脑必须共用可信的一份台账；本版只在同一 SQLite 数据库内防并发，不支持多电脑各建一份账本同时下单，也不支持与另一个自动交易系统同时运行。

紧急停止新增计划/委托：创建 `ops/KILL_SWITCH`。恢复前先核查券商持仓和未完成委托；删除开关只恢复本程序新增交易能力。**停止开关不会撤销已送达券商的委托，也不会立即清仓。**

## 7. 上线证据仍需补齐

在真实数据上重算收益、最大回撤、换手和费用敏感性，并检查样本外表现、停牌与退市样本、行业暴露和极端行情。研究引擎按复权经济单位记账，仍未精确模拟股息税、派息到账时间、配股选择、盘口排队和退市回收；不能据此承诺实盘收益。

进行前向模拟时每天保留原始数据快照、信号、当时盘口、委托与回报，衡量未成交率、实际滑点、费用、对账差额和故障恢复。模拟验证没有固定天数就能证明有效的捷径；应覆盖实际会遇到的交易和异常情况。真实小额联调的资金规模、可接受损失与停止条件需结合你的账户决定，本包未替你设定个人投资计划。

当前参数使用的佣金3 bps、最低5元、过户费用0.1 bps、卖出税费5 bps仅用于预算，实际券商可能有不同费率、包费口径或最低收费。以开户协议、现行规则和交割单核对后更新配置；不要把同一费用同时计入佣金和独立项目。
