## 先运行

使用 Python 3.11 或 3.12；MiniQMT 使用券商支持的 Windows/Python/xtquant 组合。解压后在项目目录运行：

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements-live.txt
python live.py demo
python live.py doctor
```

`outputs/v8_demo/` 会生成 2 笔合成委托计划和 2 项拦截：T+1 限制后的卖单、资金约束后的买单、未开通科创板买入、ST 买入拦截。演示日期固定，不能当作今日荐股。安装后也可以使用 `START_DEMO.bat` / `START_DEMO.command`。本机环境检查使用 `START_CHECK.bat`（Windows）或 `START_CHECK.command`（Mac），结果写到 `outputs/v9_doctor/doctor.md`。

## v9.3：真实数据每日候选 + 前向 Paper Trading

新增一条与真实券商完全隔离的前向纸面交易链路：

- `update_live_data.py`：首次完整 bootstrap，之后按最近完成交易日增量刷新 Tushare 数据；日线、复权因子、daily_basic 和涨跌停优先按交易日批量更新，新纳入成分再补历史。
- 财务信号继续按公告日做 point-in-time 过滤；数据清单显式记录 PIT 规则和 ST 历史是否降级。
- `daily_paper.py run --refresh`：收盘后生成当日真实候选；上一交易日候选只能在下一完成交易日使用真实未复权开盘价纸面成交，并用当日真实未复权收盘价记 NAV。
- `paper/live/paper.sqlite3` 是权威 Paper ledger；JSON/CSV 仅作为导出与审计副本。账户、pending intents、orders、fills、NAV 与持仓在同一 SQLite 事务中提交，崩溃前未 COMMIT 的写入会回滚。
- D 日收盘后先用 D close 固定下一开放交易日的 share intents；D+1 的 raw open 只决定 fill price，不再反推股数。漏跑预期执行日会停止，而不是静默改用更晚的 open。
- 执行层对缺失涨跌停数据采取 fail-closed，并保证滑点后的模拟成交价不越过合法涨跌停区间。
- 指数换样后，行情增量集合继续覆盖 current constituents、上一快照以及 Paper 持仓/待执行股票，避免旧持仓失去行情。
- `.github/workflows/daily-paper.yml` 在公开仓库中仅做**临时、只读**的数据链路验收：同仓库 feature 分支相关代码 push 会自动触发；合并到默认分支后也可手动触发。它不会定时运行、不会提交 Paper ledger、不会把候选/持仓/成交写回公开仓库。需要仓库 Actions Secret `TUSHARE_TOKEN`。
- **不会调用券商接口**，`live_enabled=false` 仍保持默认关闭。

详细说明见 [v9.3 真实数据 Paper Trading](docs/V9_3真实数据PaperTrading.md)。

本层使用 Tushare 日线 raw open/close 做前向纸面成交，不是 tick 级实时撮合；因此它用于验证数据、信号和执行流程，不代表真实成交能力或真实投资业绩。公开仓库不适合作为持久 Paper 状态仓库；连续 forward shadow 应在本地或私有持久存储中运行。`paper/live/` 已加入 `.gitignore`，避免本地候选、持仓、成交和账本导出被误提交到公开仓库。

## v9.2 新增实盘安全层

- **限时计划**：`plan.json` 增加 `expires_at`；登记或提交时强制检查，默认 10 分钟。
- **持久状态机**：人工复核后先落盘为 `APPROVED`，API 调用前为 `SUBMITTING`，券商受理后才是 `SUBMITTED`；支持 `PARTIAL/FILLED/CANCELLED/REJECTED/UNKNOWN/EXPIRED/BLOCKED`。
- **状态不可倒退**：例如 `SUBMITTED -> SUBMITTING` 会被拒绝，终态只允许完全一致的幂等回报。
- **本地资源冻结**：台账记录未完成买单的 `reserved_cash` 与卖单 `reserved_shares`，部分成交后递减，终态释放；`live.py ledger` 同时显示汇总。
- **Kill Switch 落盘**：在券商 API 调用前命中总开关的订单写为 `BLOCKED`，不会伪装成券商拒单。
- **旧台账无损升级**：继续使用 `ops/live_v8.sqlite3`，启动时只增加新列，不删除旧订单、券商编号或历史事件。
- **批量上限**：默认单次计划最多 60 笔，超过时整体停止，不静默截断。

## 已累计完成的主要修复

| 问题 | v8 行为 |
|---|---|
| 复权行情直接拿来判断实际涨跌停；成交额/量单位混用 | 同时保存原始价与研究复权价，金额统一元、数量统一股；交易只读未复权价格 |
| 财务修订、尚未形成的未来收益标签混入模型 | 公告日期保守延后一日；先选最近报告期再选已知修订；训练剔除未成熟标签 |
| 调仓日漏算隔夜收益，持仓权重每天免费复位 | 持续记录现金和持仓单位；保留隔夜涨跌与权重漂移；卖不出不释放资金 |
| 单股上限被优化器自动放宽，失败后静默兜底 | 不可行或约束复核失败时中止，保留错误原因 |
| 未区分复核、提交、部分成交、实际成交 | SQLite 持久状态机；APPROVED 不等于已提交；受理不记成交；超时为 UNKNOWN；未对账不重复发送 |
| 缺少行情、可卖数量、行业等仍能继续操作 | 信息不足明确阻止；全部已有持仓都计入资金和风险约束 |

## 当前启用的策略

v8 是**每日收盘后更新的固定核心策略**：沪深300历史成分并集下载，按当时可取得的最新成分快照选股；价值 30%、质量 40%、126 交易日动量 30%，执行行业和市值中性化。过滤 ST、退市风险、上市不足 180 个交易日、流动性较弱或资料不全的股票；最多 30 只，合格股票少于 15 只则停止。

沪深300收盘位于 120 日均线之上时目标总仓位至多 80%，否则至多 40%；行业限制可能使目标更低，其余保留现金。盘中用上一交易日信号和最新券商快照核算差额，1% 净资产调仓带减少小额反复交易。**这些是工程起始参数，没有用真实样本验证最优性，也未按你的资金和风险承受能力定制。**

| 默认约束 | 数值 / 范围 |
|---|---|
| 支持账户 | 沪深 A 股普通现金账户；默认只允许主板新买入 |
| 单股 / 单行业 / 总仓位上限 | 8% / 30% / 80% |
| 保留可用现金 | 至少净资产的 5% |
| 每日委托换手预算 | 买卖绝对成交金额之和 / 净资产，最多 30% |
| 单笔上限 / ADV 参与率 | 净资产的 8%、不超过10万股 / 前20交易日日均成交额的 1% |
| 买入最低经济金额 | 2,000 元；卖出不受这个下限限制 |
| 行情 / 账户最大年龄 | 30 秒 / 120 秒；未来时间也拒绝 |
| 信号价偏离 / 买卖价差 | 3% / 40 bps |
| 日亏损 / 高水位回撤触发 | 2.5% / 10%，转为只减仓计划 |
| 运行时间 | 交易日连续竞价：09:30–11:30、13:00–14:57，区间结束时刻不含 |

损失触发只在运行程序时检查，不是后台连续监控，也不能保证在跌停或停牌时卖出。一次计划不借用未成交卖单资金；卖单真实完成并对账后，再刷新账户重新规划买单。同一账户、策略、交易日、股票、方向最多登记一次，部分成交撤单后当天也不会自动追单。v9.2 的计划默认只在生成后 10 分钟内可登记/提交；超过有效期必须刷新账户和行情重新规划。订单登记后本地台账记录尚未完成买单的预留现金与卖单的预留股数，但真实可用资金/可卖数量仍以券商快照为最终事实来源。

原多股票池、ETF 轮动和 ML 模块保留为研究功能，未接入 v8 真实委托链路。v8 不支持北交所、ETF、融资融券、集合竞价、盘后交易或自动撤单追单。科创板/创业板须有实际账户权限后才可在配置中启用。

## 接入顺序

1. 在本机 `.env` 设置自己的 `TUSHARE_TOKEN`，下载完整真实数据：`python download_live_data.py`。
2. 在收盘数据完成后运行 `python live.py prepare --download`，依次下载、核查、生成信号并归档；已有最新数据时去掉 `--download`。`python live.py check` 只核查数据。
3. 盘中获取真实资金、全部持仓、可卖数量和原始行情，运行 `live.py plan`。
4. 人工复核计划后，通过人工登记或 MiniQMT 委托入口操作，并以券商回报对账。

具体命令见操作指南。`check` 未接真实数据时返回 BLOCK 是预期行为；代码测试通过不表示收益或实盘资格通过。真实委托前，须向券商确认你的程序化交易报告要求、接口开通和板块权限。不要把密码、交易验证码或 Token 发给他人。

运行完整软件测试：

```bash
python -m pip install -r requirements.txt
python -m pytest -q
```

旧版输出、收益图和旧说明放在原目录或 `docs/README_LEGACY.md`，尚未以本版和完整真实数据重算，不能作为本版业绩证明。
